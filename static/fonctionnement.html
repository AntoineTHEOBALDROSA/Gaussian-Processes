LE CALCUL PAS À PAS

Ce que fait Python à chaque étape.

Ouvrez une étape pour lire son détail. X désigne les colonnes d’entrée. On peut sélectionner plusieurs sorties ; chacune a son propre modèle.

01Lire les colonnes et préparer les observations

Le serveur lit le CSV ou la première feuille du fichier Excel d’entraînement. Vous attribuez à chaque colonne un rôle (entrée, sortie ou ignorer) et un type (numérique ou catégorie). Toutes les colonnes du fichier peuvent être sélectionnées, sans limite fixe à trois ou vingt entrées. On peut mélanger plusieurs sorties numériques et catégorielles. Les lignes incomplètes sur les variables choisies sont exclues et comptées dans les résultats. Une valeur numérique invalide est traitée comme manquante.

Les colonnes d’identification reconnues sont décochées par défaut. Le calcul exige au moins 10 observations valides et 8 configurations distinctes. Une sortie catégorielle doit avoir au moins deux classes, suffisamment représentées pour être apprises dans chaque pli. Une catégorie codée par un nombre doit être déclarée « Catégorie » si elle ne représente pas une quantité.

02Réserver le test, sans séparer les doublons

Les configurations X identiques sont regroupées, y compris leurs modalités catégorielles. Le partage aléatoire attribue environ 80 % des configurations à l’apprentissage et 20 % au test final. Un groupe entier appartient à un seul ensemble, même si ses valeurs Y diffèrent.

Ces 20 % correspondent à la validation finale, appelée test ici. Les plis de validation croisée sont pris uniquement dans les 80 % d’apprentissage. La validation croisée respecte aussi ces groupes. Cela évite de valider le modèle sur une configuration qu’il a déjà vue. Pour une classification, le partage est recherché à partir de la graine 2025 afin que chaque classe soit présente dans l’apprentissage de chaque pli. La graine de partage retenue est affichée. Les scores du test final ne servent ni à apprendre les paramètres ni à choisir les noyaux.

03Mettre les variables à une échelle comparable

Dans chaque pli, les catégories d’entrée sont encodées en colonnes indicatrices (one-hot), sans imposer d’ordre entre les modalités. Cet encodage est appris sur les seules observations d’apprentissage du pli. Les colonnes obtenues sont ensuite centrées et réduites. Chaque sortie numérique est elle aussi centrée et réduite ; une classe de sortie reste une étiquette. Les mêmes transformations sont appliquées à la validation.

X̃i = (Xi − mi) / siỸ = (Y − mY) / sY

La normalisation évite qu’une variable domine le calcul simplement à cause de son unité. Les prédictions et leurs écarts-types sont ensuite remis dans les unités originales de Y. Pour une variable constante, le diviseur vaut 1. Une modalité inconnue dans un pli ou dans le test est encodée par un vecteur nul et signalée dans les résultats du test. Lors d’une nouvelle prédiction, une modalité inconnue est refusée pour éviter une prédiction ambiguë.

04Comparer les familles de noyaux par validation croisée

Le noyau décrit la similarité entre deux configurations et les variations que le modèle peut représenter. Pour chaque candidat, Python entraîne un modèle sur tous les plis sauf un, prédit le pli réservé et mesure sa RMSE (régression) ou sa log-loss (classification). Il recommence jusqu’à ce que chaque pli ait servi à la validation. Chaque tour repart d’un nouveau modèle : il ne reprend ni les paramètres appris, ni les prédictions du tour précédent. La flèche de retour du schéma signifie « passer au pli suivant ».

Chaque sortie a un classement indépendant : moyenne des RMSE pour une sortie numérique, moyenne des log-loss pour une classe. On préfère le score le plus faible, avec les mêmes partitions pour tous les candidats. L’écart-type affiché décrit la variation du score entre plis ; ce n’est pas l’incertitude d’une prédiction.

LES NOYAUX EN 1D

Une formule, une forme.

1 / 8

Les mêmes six observations, les mêmes axes et des paramètres fixes pour comparer les noyaux. La courbe bleue est la moyenne prédite ; la zone pâle est son intervalle à 95 %.

RBF

Une interpolation très lisse, avec des transitions régulières.

k(x, x′) = exp(−r² / 2)

r = |x − x′| / ℓ · ℓ = 0,85

La longueur ℓ contrôle la vitesse à laquelle la courbe peut varier.

Formules du signal en 1D, avec une amplitude fixée à 1 et une variance de bruit de 0,0001. Ici, les paramètres ne sont pas optimisés. Dans l’outil, ils sont appris à partir de vos données. Les noyaux linéaire et quadratique ajustent une tendance et ne passent pas nécessairement par chaque observation.

En régression, les noyaux incluent une amplitude et un bruit d’observation. La classification utilise une vraisemblance logistique, pas un bruit gaussien ajouté aux étiquettes. Les vignettes ci-dessus montrent uniquement des exemples de régression 1D. ARD signifie qu’une longueur de corrélation ℓi est apprise séparément pour chaque entrée.

La recherche trouve le meilleur score parmi ces candidats et ces réglages. Elle ne garantit pas le meilleur noyau possible, ni un optimum global de ses paramètres.

05Optimiser les paramètres et calculer le processus gaussien

Pour une famille donnée, l’optimiseur L-BFGS-B ajuste les paramètres θ par vraisemblance marginale sur l’apprentissage. Pour une classification GP, cette vraisemblance est approchée par la méthode de Laplace ; les probabilités sont intégrées par quadrature numérique. Le multiclasse utilise un GP binaire par classe, puis normalise les probabilités (un contre tous). Selon le noyau, θ contient l’amplitude, les longueurs ℓi, le bruit ou d’autres paramètres. La recherche respecte les bornes configurées et utilise des relances depuis différentes initialisations.

Les relances essaient d’autres paramètres de départ pour éviter de retenir une mauvaise solution locale. Le mode complet en effectue 10 lors du réentraînement final ; le mode rapide en effectue 1. On conserve la solution avec la meilleure vraisemblance sur l’apprentissage.

Une longueur est exprimée dans l’espace standardisé. Une grande longueur correspond à une variation lente selon cette entrée ; elle ne suffit pas, à elle seule, à mesurer son importance. Une borne atteinte est un diagnostic à examiner : un bruit proche de zéro peut être cohérent avec des simulations déterministes.

06Réentraîner et mesurer la qualité finale

Pour chaque sortie, après son classement, un nouveau modèle avec la famille gagnante est ajusté sur l’ensemble des 80 % d’apprentissage, avec les relances finales. Il recalcule ses normalisations et ses paramètres. Le modèle conservé par le site reste entraîné sur ces 80 %.

Chaque modèle prédit ensuite les 20 % de test réservés. Pour les classes, le site affiche la matrice de confusion, l’exactitude, le F1 macro et la log-loss. Pour les sorties numériques : La RMSE accentue les grandes erreurs ; la MAE mesure l’erreur absolue moyenne. La couverture mesure la part des observations de test dans l’intervalle prédictif μ ± 1,96σ.

Un intervalle nominal à 95 % n’est pas une garantie.

La couverture réelle dépend des données et du modèle. Le test final sert à constater sa qualité ; utiliser plusieurs fois son score pour choisir les réglages finirait par biaiser cette évaluation.

Les coupes 1D font varier une entrée en fixant les autres à leur médiane numérique ou à leur modalité la plus fréquente dans l’apprentissage. Pour une sortie catégorielle, les coupes montrent les probabilités de chaque classe. Les observations affichées sur une coupe sont projetées sur son axe : elles ne correspondent pas nécessairement à ces mêmes valeurs fixes.

+Comment les configurations à mesurer sont-elles choisies ?

La vue Plan d’expériences prépare les configurations de vos prochaines simulations. Créer un plan LHS répartit les points selon les lois choisies, sans consulter les prédictions ni les incertitudes du modèle : c’est utile pour démarrer une campagne. Enrichir avec le modèle entraîné utilise les observations et le modèle pour chercher des zones éloignées et incertaines : c’est utile pour compléter une campagne existante. Le graphe superpose l’apprentissage, le test réservé et les propositions sur les axes choisis.

  1. Choisir pour chaque entrée numérique une loi uniforme, normale tronquée ou log-uniforme, avec ses bornes et, pour la normale, sa moyenne et son écart-type. Les catégories ont des modalités autorisées et des poids réglables. Les valeurs entières sont discrétisées.
  2. Ajouter des comparaisons entre variables ou constantes, des intervalles inclus/exclus, des catégories autorisées ou interdites, une somme pondérée (par exemple 2 × X1 + X2 ≤ 10) ou un écart absolu entre deux valeurs. Toutes les conditions sont appliquées ensemble. Une égalité de somme utilise la tolérance choisie. Aucune expression Python n’est exécutée.
  3. Tirer des quantiles LHS, appliquer les lois marginales puis rejeter les configurations qui violent les contraintes. Retirer les doublons et, si demandé, les observations connues. La recherche s’arrête après un budget de 50 000 tirages ou 64 lots ; si le domaine est trop contraint, le site le signale et peut renvoyer moins de points.
  4. Pour un plan initial, renvoyer jusqu’à 3 000 points sans entraîner de modèle. Pour un enrichissement, former un réservoir (4 096 candidats par défaut, réglable jusqu’à 32 768), puis retenir de 1 à 200 points.
  5. En enrichissement : combiner la distance aux observations avec l’incertitude. Pour une sortie numérique, soustraire le bruit d’observation pour obtenir l’écart-type de la fonction. Pour une classe, utiliser l’entropie des probabilités. Si plusieurs sorties sont prises en compte, moyenner leurs rangs d’incertitude à poids égaux, indépendamment des unités.
  6. Un filtre optionnel peut cibler une plage numérique prédite ou une classe prédite. Diversifier ensuite le lot. Ces prédictions peuvent être différentes des futures mesures.

La contrainte prime sur la stratification. Rejet, exclusion des points connus, arrondi et sélection d’un sous-ensemble peuvent modifier les strates LHS et les proportions marginales finales. Une égalité exacte entre variables continues peut être impossible à obtenir par rejet. Les marges paramétrées ne définissent pas une corrélation jointe entre entrées.

Le CSV exporte les entrées et toutes les sorties à mesurer, laissées vides. Les prédictions ne deviennent pas automatiquement des observations. Les contraintes vérifiées sont celles que vous avez saisies ; les autres contraintes physiques du système restent à définir.

CUDA accélère la régression avec les quatre noyaux simples ; la banque élargie et la classification utilisent le CPU. Le diagnostic vérifie un calcul GP float64, son gradient et sa prédiction ; un échec est expliqué, sans bascule CPU cachée. PyTorch compatible CUDA doit être installé dans le Python indiqué par le diagnostic. La mémoire GPU et le pilote doivent être accessibles à la session du serveur.

Après une modification Python, il faut redémarrer le serveur ; les modèles déjà entraînés conservent leurs paramètres.

Le bouton unique « Exporter le rapport complet (PDF) » inclut un sommaire cliquable, toutes les sorties, leurs métriques et graphiques, les paramètres, les paires d’entrées, le dernier plan généré et une annexe contenant toutes les données importées. Il ne dépend pas de l’onglet visible ni des graphiques déjà ouverts.
